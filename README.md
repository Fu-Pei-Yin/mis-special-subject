# MINDGUARD：社群憂鬱傾向偵測模型（畢業專題）

> 多模態生成式 AI－社群憂鬱傾向偵測外掛系統｜以 Threads 公開貼文為資料，訓練使用者層級的二元風險分類模型。本儲存庫收錄四支模型訓練腳本，比較兩種序列編碼器（BiLSTM、Transformer）與兩種特徵設計（一般型、邏輯特徵型）。

## 摘要（Abstract）

社群平台上的貼文，常是憂鬱情緒最早出現的地方。但要從大量貼文中判讀風險，靠人工既慢又難以規模化。

本專題以 Threads 公開貼文為研究對象，建立使用者層級的分類模型：一個帳號在近 14 天內的貼文與個人簡介，整合成一筆樣本，輸出「高風險」或「低風險」。模型以 Sentence-BERT 取得中文語意向量，再用序列編碼器整合多篇貼文，最後與簡介向量及數值特徵融合，交給多層感知機分類。

儲存庫中的四支腳本，是兩個設計問題的交叉比較：

1. 用 **BiLSTM** 還是 **Transformer** 編碼貼文序列？
2. 只用語意與基本統計特徵（**一般型**），還是加入詞彙規則特徵、資料增強與更強的正則化（**邏輯特徵型**）？

## 研究動機（Motivation）

憂鬱傾向的判斷不只看單篇貼文。同一位使用者的發文頻率、深夜活躍程度、簡介用語，都可能是訊號。因此本專題把分析單位從「一篇貼文」提高到「一位使用者」。

另一個考量是可解釋性。單看分類結果，使用者與研究者都難以判斷模型的依據。邏輯特徵型腳本加入人工設計的正負向詞彙特徵，是為了讓模型的判斷有一部分能對應到可讀的線索。

## 研究流程（Pipeline）

```
Threads 公開貼文（爬蟲蒐集）
        │
        ▼
兩階段標註（帳號篩選 → 症狀事件標註）
        │
        ▼
使用者層級整併：一個帳號 = 一筆樣本
        │
        ▼
特徵萃取
  ├─ 貼文：Sentence-BERT 向量序列（最多 32 篇）
  ├─ 簡介：Sentence-BERT 向量
  ├─ 數值特徵：發文量、平均長度、深夜比例等
  └─ （邏輯特徵型）詞彙規則特徵
        │
        ▼
序列編碼（BiLSTM 或 Transformer）→ 特徵融合 → MLP → 二元分類
        │
        ▼
分層 5 折交叉驗證
```

本儲存庫涵蓋「特徵萃取」到「交叉驗證」。爬蟲、標註與可解釋介面不在此儲存庫。

## 四支腳本的比較（Model Variants）

| 腳本 | 編碼器 | 特徵 | 訓練設定 |
| --- | --- | --- | --- |
| `general_llm_model(LSTM).py` | 雙向 LSTM（隱藏層 256、2 層、dropout 0.3），取最後一層前後向隱藏狀態 | 數值特徵 4 項 + 簡介向量 | 15 輪；權重衰減 1e-5；依驗證準確率調整學習率與提前停止 |
| `general_llm_model(transformer).py` | Transformer Encoder（1 層、4 頭、前饋維度 256、dropout 0.2），對序列做平均池化 | 數值特徵 4 項 + 簡介向量 | 15 輪；權重衰減 1e-5；無學習率調度與提前停止 |
| `logic_llm_model(lstm).py` | 雙向 LSTM（隱藏層 256、2 層、dropout 0.3），加 LayerNorm 與投影層 | 數值特徵 6 項 + 邏輯特徵 5 項 + 簡介向量 | 最多 30 輪；權重衰減 1e-4；資料增強；依驗證 F1 調整學習率與提前停止 |
| `logic_llm_model(transformer).py` | Transformer Encoder（2 層、4 頭、前饋維度 256、dropout 0.3），加 LayerNorm，平均池化 | 數值特徵 6 項 + 邏輯特徵 5 項 + 簡介向量 | 同上 |

### 共同設定

| 項目 | 設定 |
| --- | --- |
| 文字嵌入模型 | `paraphrase-multilingual-MiniLM-L12-v2`（384 維） |
| 每位使用者最多納入貼文數 | 32 篇；不足以零向量補齊 |
| 資料切分 | 分層 5 折交叉驗證，以使用者為單位，隨機種子 42 |
| 損失函數 | `BCEWithLogitsLoss`，正類權重 = max(1, 負類數 ÷ 正類數)，處理類別不平衡 |
| 優化器 | AdamW，學習率 1e-3，批次大小 4 |
| 梯度裁剪 | 最大範數 1.0 |
| 分類門檻 | 機率 ≥ 0.5 判為高風險 |
| 分類頭 | 兩層 MLP（128 → 64 → 1），dropout 0.3（邏輯特徵型為 0.4） |
| 特徵標準化 | `StandardScaler` |

### 特徵說明

**數值特徵（一般型 4 項）**

| 特徵 | 意義 |
| --- | --- |
| `post_count` | 該使用者貼文數 |
| `avg_post_len` | 貼文平均字數 |
| `bio_len` | 簡介字數 |
| `night_ratio` | 凌晨 0 至 5 點發文比例 |

邏輯特徵型另加 `max_post_len`、`min_post_len`，共 6 項。

**邏輯特徵（邏輯特徵型 5 項）**

| 特徵 | 意義 |
| --- | --- |
| `neg_count` | 負向詞彙出現次數（10 個詞，如「痛苦」「沒意義」「撐不住」「絕望」） |
| `pos_count` | 正向詞彙出現次數（7 個詞，如「開心」「期待」「感謝」「平靜」） |
| `logic_score` | 負向次數減正向次數 |
| `bio_flag` | 簡介是否含「抑鬱」「憂鬱」「低潮」「焦慮」 |
| `neg_ratio` | 負向詞占所有情緒詞的比例 |

**資料增強（邏輯特徵型）**

訓練時，每筆樣本有 30% 機率在貼文與簡介向量上加入標準差 0.05 的高斯雜訊。驗證時不加。

## 資料（Data）

原始資料不公開。資料來自 Threads 公開貼文，涉及個人發文內容，僅限研究使用。

腳本預期的 Excel 檔，需含下列欄位：

| 欄位 | 內容 |
| --- | --- |
| `username` | 帳號 |
| `display_name` | 顯示名稱 |
| `bio` | 個人簡介 |
| `post_content` | 貼文內容 |
| `post_date` | 貼文時間 |
| `depression_or_not` | 二元標籤（1 為高風險，0 為低風險） |

同一帳號的多列資料，會依時間排序後整併為一筆樣本；該帳號的標籤取所有列的最大值。

**資料集規模（主要實驗）：** 593 位使用者，其中高風險 194 位、低風險 399 位。不確定的觀察帳號不納入二元訓練。

**標註方式：** 分兩階段。第一階段篩選帳號，排除商業帳號、公眾人物帳號與內容不足的帳號。第二階段依 11 類症狀事件標註，類別由 PHQ-9 延伸而來，貼文中證據不明確時一律標為否。

## 研究成果（Results）

以下為專題報告的評估結果。這些指標的計算流程（含信賴區間與 ROC-AUC）不在本儲存庫的腳本中；腳本本身只輸出準確率、精確率、召回率與 F1。

**五折交叉驗證（一般型 BiLSTM，最終採用的模型）**

| 指標 | 平均 | 標準差 | 95% 信賴區間 |
| --- | --- | --- | --- |
| F1 | 0.9013 | 0.0157 | [0.8687, 0.9299] |
| Precision | 0.9059 | 0.0204 | [0.8644, 0.9441] |
| Recall | 0.8967 | 0.0218 | [0.8508, 0.9355] |
| ROC-AUC | 0.9551 | 0.0107 | [0.9323, 0.9737] |

**外部驗證（100 位未參與訓練的帳號）**

| F1 | Precision | Recall | ROC-AUC | PR-AUC |
| --- | --- | --- | --- | --- |
| 0.8632 | 0.9111 | 0.8200 | 0.9700 | 0.9715 |

**人工裁決黃金標準測試集（111 位帳號，高風險 14、低風險 97）**

| Accuracy | Precision | Recall | F1 | AUROC | 漏判數 |
| --- | --- | --- | --- | --- | --- |
| 0.7117 | 0.2955 | 0.9286 | 0.4483 | 0.9282 | 1 |

這組測試集的類別極度不平衡。模型偏向不漏判，因此召回率高、精確率低。標註一致性以 Cohen's κ 衡量，數值為 0.966 與 0.921。

## 安裝與執行（Installation）

**環境需求：** Python 3 與 PyTorch；建議使用 GPU，也可在 CPU 上執行。

```bash
git clone https://github.com/Fu-Pei-Yin/mis-special-subject.git
cd mis-special-subject

pip install torch sentence-transformers scikit-learn pandas numpy openpyxl tqdm joblib
```

**執行前需要做的事：**

1. 準備符合上述欄位的 Excel 檔。
2. 修改腳本開頭的 `DATA_PATH`，改成你的檔案路徑。腳本內預設為作者本機路徑。
3. 執行想比較的腳本：

```bash
python "general_llm_model(LSTM).py"
python "logic_llm_model(lstm).py"
```

第一次執行時，會自動下載 Sentence-BERT 模型。

**輸出檔案**

| 腳本 | 輸出資料夾 | 主要檔案 |
| --- | --- | --- |
| 一般型 × LSTM | `saved_user_model_lstm/` | `user_model_lstm.pt`、`numerical_scaler.pkl`、`cv_results_lstm.csv`、`meta.json` |
| 一般型 × Transformer | `saved_user_model/` | `user_model.pt`、`numerical_scaler.pkl`、`cv_results.csv`、`meta.json` |
| 邏輯特徵型（兩支） | `saved_user_model/` | `fold_1_best.pt` 至 `fold_5_best.pt`、`numerical_scaler.pkl`、`logic_scaler.pkl`、`cv_results.csv`、`meta.json` |

## 限制與未來工作（Limitations and Future Work）

**限制**

- **兩支邏輯特徵型腳本與一般型 Transformer 共用輸出資料夾。** 依序執行時，後者會覆蓋前者的 `meta.json`、`cv_results.csv` 與標準化器。要比較不同腳本，請在每次執行之間改 `OUTPUT_DIR`。
- **一般型腳本保存「最佳輪次」的方式有疑慮。** 兩支一般型腳本用 `model.state_dict().copy()` 保存最佳權重。這是淺層複製，張量仍與模型共用記憶體，之後的訓練會繼續改動它。載回的權重可能其實是最後一輪，而非最佳輪。這是依 PyTorch 的行為推論，我沒有在本機實測。邏輯特徵型腳本改為把權重存成檔案，沒有這個問題。
- **選模型與報告用同一組驗證資料。** 四支腳本都以驗證折的指標挑選最佳輪次，再報告同一折的成績，結果會偏樂觀。專題另以外部帳號與黃金標準集驗證，正是為了補足這一點。
- **邏輯特徵型的標準化在切分之前。** 兩支邏輯特徵型腳本對全部資料一次擬合 `StandardScaler`，再切折。驗證折的統計量因此進入了訓練用的縮放。一般型腳本是每折各自擬合，沒有這個問題。
- **沒有遮罩處理補齊的位置。** 貼文不足 32 篇時以零向量補齊，BiLSTM 與 Transformer 都把補齊的位置當成真實輸入。貼文少的使用者，受補齊影響較大。
- **詞彙規則很小。** 負向與正向詞彙共 17 個，採子字串比對，「累」這類單字詞可能誤中其他詞彙。簡介關鍵詞只有 4 個。
- **分類門檻固定為 0.5。** 在類別極度不平衡的測試集上，這個門檻不一定合適。
- **資料與環境不完整。** 儲存庫沒有資料、爬蟲、標註流程或 `requirements.txt`，`DATA_PATH` 也是本機路徑。他人無法直接重現結果。

**未來工作**

- 把最佳權重改為深層複製（`copy.deepcopy`）或存檔，並修正兩支一般型腳本。
- 拆出獨立的測試折，讓選模型與報告分開。
- 在切分後才擬合標準化器。
- 加入注意力遮罩，或改用 `pack_padded_sequence`，避免補齊位置影響編碼。
- 以驗證集校準分類門檻，並報告機率校準結果。
- 把資料路徑與輸出資料夾改為命令列參數，並補上 `requirements.txt`。
- 把爬蟲、標註規範與可解釋介面整理成獨立儲存庫，與本儲存庫互相連結。
- 延伸至可信任的多模態大型語言模型：評估回答的可靠度，並設計可解釋的使用介面。
